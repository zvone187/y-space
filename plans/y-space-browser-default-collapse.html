Implementation Plan

One browser. One work disclosure. One final answer.

The live run had Y Space Browser connected, but OpenCode chose a globally discovered gstack browser. This plan makes the embedded browser the only model-visible browser route and folds each turn's intermediate work into one closed row.

Fast Answer

Observed failure

The exact OpenCode task loaded /browse, ran gstack's separate Chromium, and emitted no Y Space Browser MCP calls while the visible embedded page stayed unchanged.

Capability boundary

Force the built-in browser MCP on, filter competing browser MCPs, hide provider web/search/browser skills, and inject one provider-neutral Y Space Browser directive.

Transcript boundary

Project each user turn into one closed work group plus the tail assistant response. A streaming tail response stays visible; if a later tool arrives it moves into the closed group.

Architecture Decisions

Shared invariant

spawnPipeline keeps Y Space Browser present and removes snapshot MCPs classified as Playwright, Chrome, Puppeteer, Selenium, gstack, browser-use, or equivalent.

Provider isolation

OpenCode loses native web/search/skill and external browser MCP access; Claude gets strict MCP, no Chrome, no provider skills, and no WebFetch/WebSearch; Codex loses browser features, live search, browser skills, and browser-backed MCPs.

No profile mutation

The app applies launch-scoped overlays only. It does not uninstall, rewrite, or expose the contents of the user's normal OpenCode, Claude, or Codex profiles.

Implementation Map

Browser policy

  • Add a shared browser-exclusive instruction and MCP classifier.
  • Enforce it in OpenCode terminal/SDK, Claude terminal/SDK, and Codex TUI/app-server.
  • Keep Pipedream and unrelated integrations intact.
  • Strengthen Browser MCP API guidance to say sole/default browser.

Collapsed work

  • Add a compact top-level timeline selector.
  • Group reasoning, status narration, tools, commands, edits, searches, and browser calls.
  • Render the group closed by default with manual expansion.
  • Auto-close on completion and leave only the final assistant body open.

TDD User Stories

Visible browser proof

When a user asks an agent to test a localhost app, the visible Y Space browser page must navigate and change; provider browser skills, native web tools, and Playwright must not appear in the effective catalog.

Streaming transcript

While work runs, intermediate narration and operations remain behind one closed row. A tail assistant candidate is readable until a later operation demotes it into that row.

Settled transcript

After turn.completed, the work row is closed and the final assistant response is the only expanded content. Users can still open the work row and inspect every retained item.

Verification & Risks

Required evidence

  • Fail-first provider and selector/component tests.
  • Focused suites, full Node 24 suite, typecheck, lint, build, unsigned package.
  • Computer Use click-test of exact packaged app and isolated profile.
  • Visible URL/DOM change in embedded Browser and no external browser process/path.

Known external gate

Claude Code 2.1.210 is installed but logged out. We can fully verify its launch contract and packaged UI availability, but real Claude inference requires the user to authenticate; no credentials will be entered on their behalf.

Open The Cards

  • Provider-neutral resolved MCP descriptors and the three provider launch adapters.
  • Canonical runtime events, completed-turn boundaries, virtualized chat rows, disclosures, and existing tool/reasoning accordions.
Changed modules

  • src/supervisor/agents/opencode, claude, and codex launch/SDK/config translators.

  • chatPaneSelectors.ts, MessageList.tsx, ChatItemRow.tsx, ToolCallGroup.tsx, and a new work disclosure component.

Options rejected
  • Prompt-only steering: the failing run proves a stronger discovered skill can win.
  • Uninstalling or rewriting global tools: destructive to the user's other workflows and unnecessary.
  • Only collapsing consecutive tools: leaves the exact status narration that caused the complaint visible.
  • Nested browser tabs: violates the existing one-global-tab concept and increases browser residency.
Dependencies and cleanup
No new package is required. The implementation reuses the existing disclosure, state, MCP translation, TOML parsing, and provider SDK surfaces. Provider-specific legacy external-browser paths are suppressed at launch; user-owned global configuration remains untouched.
