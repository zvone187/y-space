Implementation plan

Y Space, stripped back

A white-first, warm-neutral, orange-accent redesign that removes ambient developer statistics and redundant chrome while preserving every agent, browser, file, document, and global-tab workflow.

01 — Summary

The request resolves the visual direction; no additional product decision is required.

Goal

Make Y Space feel calm and approachable rather than like an IDE: white canvas, subtle warm gray hierarchy, sparse orange accents, and one clear action per area.

Agreed approach

Restyle shared tokens first, then simplify ambient navigation/header/composer chrome. Keep detailed Git and runtime information available only inside dedicated views, tooltips, hover controls, or menus.

Decisions
  • Fresh profiles launch light; explicit saved dark mode remains supported but uses orange branding.
  • Remove visible +N/-N, sync counts, PR numbers, and default usage rings from ambient chrome.
  • Preserve exactly one global workspace tab strip; consolidate the separate right-panel tool rail into a compact add/overflow affordance.
Dependencies

No new libraries or packages. Reuse existing HeroUI v3, Tailwind utilities, Lingui, Lucide, and theme infrastructure.

02 — Existing implementation

Reuse unchanged
  • BrowserPanelManager, Browser MCP, cookie import, Pipedream, provider runtimes.
  • Global workspace-tab state, keyboard navigation, reorder, close focus, persistence, and webview LRU.
  • Dedicated Git/diff surfaces and shared DiffStat inside those detail views.
  • Existing HeroUI controls and responsive composer behavior.
Change
  • styles.css, theme presets/defaults, initial document paint, and brand assets.
  • Sidebar task rows, Git/sync affordances, usage rail default, and footer/header density.
  • Thread header, ambient changes affordance, composer surface, and right-panel chrome.
  • Visual tests, first-paint/theme tests, QA plan, and screenshots.

03 — New implementation

Foundation

Default palette: white canvas, #FBFBFA subtle surfaces, #181816 text, #EEEDE9 hairlines, accessible #FF5A1F orange actions, and pale orange selection/focus tints.

Navigation

One-line task rows with title, state, and age; hover/focus actions stay accessible. Remove visible diff/sync counts and default usage rings. Consolidate secondary footer actions into overflow.

Workspace

Flatten global tabs to text labels with one orange selected indicator. Remove the redundant always-visible tool rail; tools still create peer tabs through a compact menu.

Conversation

Reduce the header to status, title, and essential actions/overflow. Keep assistant content flat and user prompts softly tinted.

Composer

One white rounded input card with a hairline border, soft shadow, restrained controls, and an orange enabled Send/Stop action. Changes remain available as one icon-only review affordance.

Brand assets

Replace the legacy indigo/dark-first icon palette across stable SVG masters, public icon, generation constants, and brand documentation; regenerate platform outputs.

04 — Tests and user stories

User stories

  • As a non-developer, I can understand my tasks without Git statistics or tool noise competing with their titles.
  • As an agent user, I can still reach files, Git, browser pages, documents, settings, and advanced actions when needed.
  • As a browser user, every page remains an independent peer in the one global tab strip and retains state while I move elsewhere.
  • As an accessibility user, hidden visual metadata remains available through names, tooltips, menus, focus, and keyboard navigation.

Failing tests before production code

  • Fresh settings and first paint require light mode; default theme anchors require white/warm-neutral/orange and prohibit legacy indigo.
  • GitBadge, SyncBadge, and ThreadChangesBubble require glyph-only ambient controls with no visible counts while preserving accessible labels and click behavior.
  • Default usage rail is off; explicit opt-in remains valid.
  • Global tab strip requires flat styling, one selected indicator, and unchanged tab semantics.
  • Brand source SVGs/build constants require the orange/white system and reject #8B7BFF.

Acceptance criteria

  • Fresh packaged app opens white with no black flash and no purple/indigo default-brand surfaces.
  • Idle sidebar/composer chrome contains no visible line, file, sync, PR, token, or usage counts.
  • All advanced actions remain keyboard- and screen-reader-accessible.
  • Files, Git, two browser pages, PDF/XLSX, Notes, Usage, and Terminal remain global peers with browser state preserved.
  • All unit/integration tests, typecheck, lint, format, i18n, build, codesign, manual 1440×900 and 1024×768 QA, and browser lifecycle regression pass.

05 — TDD implementation order

  2. Implement theme/default/asset foundation and regenerate icons.

  3. Simplify Git/sync/changes/usage/sidebar chrome while preserving behavior and accessibility.

  4. Consolidate right workspace tools into the global strip, then simplify thread header and composer.

  5. Run targeted and full suites, build the unsigned ARM64 package, and manually click both viewport sizes plus browser/global-tab regressions.

06 — Risks and mitigations

Hidden functionality

Over-trimming can make power features undiscoverable. Keep every removed ambient action in an overflow, tooltip, hover/focus state, or dedicated peer tab; verify keyboard and accessible names.

Theme persistence

Fresh profiles become light, while explicit saved appearance remains respected. Manual QA will set the local Y Space profile to light so the user’s current machine receives the requested appearance.

Browser regressions

Do not change browser ownership or workspace-tab state. Keep the existing global-tab/browser suites unchanged and rerun lifecycle/memory checks proportionate to the presentational diff.

HeroUI helper unavailable

The repository-requested heroui-react skill is unavailable in this session. Reuse existing HeroUI v3 primitives and local patterns only; add no substitute UI dependency.
