# Y Space implementation pass criteria

The implementation is complete only when every criterion below is satisfied. A criterion may not be waived by a green unit test if the corresponding desktop workflow has not also been click-tested.

Prior outcome on `y-space-minimal-branding` (2026-08-28): the implementation-owned browser, global-tab, minimal-branding, contrast, typography, footer, packaging, and read-only integration work is complete. Live Claude inference and persistent Pipedream OAuth/account-grant workflows remain external authorization gates, and Chrome/Brave extension installation remains intentionally deferred by user direction. The structured result and screenshots are recorded in `implementation assets/qa-e2e-tests.json`.

Current follow-up on `y-space-browser-default-collapse` (2026-08-28): implementation and final unsigned-package verification are complete, subject only to the pre-existing Claude login and persistent Pipedream OAuth authorization gates. OpenCode and Codex now operate the visible Y Space Browser as their launch-scoped default and sole browser route, while each turn renders one closed Codex-style work disclosure with the final response left visible. Post-audit hardening keeps adapters without an exclusive embedded-browser route launchable without silently enabling Browser, while an explicit unsupported Browser request still fails closed. The criteria below are additive; prior evidence remains retained as historical coverage.
