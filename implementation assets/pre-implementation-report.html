Pre-implementation report

Embedded browser by default. Quiet turns by default.

The exact failing OpenCode task had Y Space Browser connected but selected a discovered gstack browser and separate headless Chromium. The visible embedded page never changed. This implementation will make Y Space Browser the sole launch-scoped browser route and present every turn as one closed work row plus the final answer.

Observed defect and invariant

Live proof

  • OpenCode loaded /browse from the discovered gstack skills.
  • It ran a separate headless Chromium and saved screenshots under /tmp.
  • No Y Space Browser MCP event appeared, although the MCP was connected.
  • The visible Y Space page stayed on Claude Login while the transcript claimed browser testing.

New invariant

  • Y Space Browser is forced on unless the global Browser hard-disable is active.
  • When present, it is the sole model-visible route for browser navigation, interaction, inspection, and screenshots.
  • Policy overlays are per launch and never mutate normal provider profiles.
  • Unrelated MCPs, explicit Y Space skills, and Pipedream remain intact.

End-to-end verification plan

OpenCode

Run two configured models in the exact unsigned package. Each must visibly navigate and mutate a localhost page, enumerate the global browser tabs, reuse a tab, and close a disposable peer without gstack, Playwright, native web tools, or an external browser process.

Codex

Repeat in GUI and terminal presentation. Record the visible embedded state, Browser MCP events, launch overrides, and unchanged normal profile. Native browser/search routes must not appear.

Claude

Verify terminal and SDK launch contracts while logged out. Live inference remains an explicit user-authentication gate; after login, repeat the same visible localhost scenario without entering credentials on the user's behalf.

Streaming turn

Confirm one initially closed Working row, no mounted heavy body, persistent manual expansion, a visible tail answer candidate, and correct demotion of that candidate when a later tool arrives.

Settled turn

Confirm the row auto-closes and only the final answer remains expanded. Reopen it, inspect retained chronology, search hidden text, and verify questions/user messages stay outside.

Cleanup

Repeat browser-tab churn in an isolated profile. Enforce six live ordinary guests and thirty metadata entries, return to baseline after cleanup, leave no helper after quit, and restore no disposable pages.

Risks and controls

Provider configuration precedence
Prompt steering alone is insufficient. Enforcement must occur after provider/global discovery and after permissive wildcard rules, with tests for both terminal and structured launch paths.
Transcript virtualization and Find
The compact display type stays separate from the raw canonical timeline. Group rows expose stable IDs and underlying item IDs so measurement, completion anchors, search mapping, subagents, and history remain correct.
Memory and browser residency
Closed work bodies are unmounted. Existing browser LRU limits remain unchanged: six ordinary live webviews, four sensitive live webviews, and thirty ordinary metadata entries. Repeated packaged cleanup is a release gate.
External authorization
Claude Code 2.1.210 is installed but loggedIn=false. Launch behavior can be fully verified now; a real Claude inference/browser run cannot honestly pass until the user authenticates. No Pipedream OAuth/account grant or provider credential mutation is part of this follow-up.

Decision

Ready Production implementation may begin.

No new dependency is planned. The work reuses the provider adapters, resolved MCP transport, canonical runtime events, disclosures, virtualized list, browser lifecycle controls, and existing packaging workflow. Completion requires focused and full verification, an unsigned package, hands-on Computer Use proof, a Husky-validated commit, and a stacked pull request. No merge or force push is authorized.
