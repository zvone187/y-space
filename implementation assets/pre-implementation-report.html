Implementation boundaries

Surface rebrand

Visible product identity becomes Y Space. Existing Poracode/Lightcode storage, protocol, migration, environment, MCP, and browser-partition identifiers remain stable where changing them could lose data.

One agent browser

Agents control only the embedded browser. The old external Chrome MCP/control stack is retired. The companion extension is a user-operated cookie source only.

Provider-neutral core

Codex, Claude Code, and OpenCode receive Browser, app controls, exact task identity, tab overview/search, and Y Space core skills by default.

Two Pipedream modes

Personal MCP reuses managed OAuth. BYO Connect keeps credentials server-side and exposes app/account bindings only through an authenticated loopback relay.

One global workspace

Files, Git, Usage, Notes, Browser, Terminal, transient plan/subagent surfaces, and source/PDF/spreadsheet documents share one ordered outer strip. Browser page tabs remain nested so their webviews and agent connection stay alive while other tabs are selected.

Security and approval gates

Secret boundary

  • Delete Pipedream values from main and supervisor environment before agent spawn.
  • Never log or expose cookie values, developer/Connect tokens, or raw upstream errors.
  • Renderer receives metadata/counts only.

Authority boundary

  • Agents control only persist:lightcode-browser.
  • Cookie extension cannot list, attach, navigate, inspect, or drive external tabs.
  • Provider-session identity is trusted only after supervisor resolution.

Side-effect boundary

  • Account ownership is revalidated before enable/delete.
  • Relay binds sessions to one account and never retries tools/call on 401.
  • Manual QA uses harmless/read-only actions except explicit confirmed disconnect.
